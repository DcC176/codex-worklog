## 每日发布

- 每天北京时间 **00:15**，由本机 Codex 定时整理前一天的工作并推送到此仓库。
- 记录来源是本机 Codex 的活动与归档会话，以及 WorkBuddy、旧 WorkBuddy AI 目录中的主会话；不保证覆盖其他设备、云端或未落盘的工作。
- 相同日期更新同一篇日志，不重复创建文件；没有工作记录时如实记载，不编造进展。
- 每日任务从 2026-10-14 起检查缺失日期并补齐；更早记录已单独补记。已有“阶段记录”的日期在日终重新整理。
- 本机需要开机、联网、Codex 应用运行且 GitHub 登录有效；这不是脱离本机运行的云端任务。

## 内容规则

每篇日志记录：今日概览、工作进展、验证与限制、后续事项。只将有完成依据的事项写为完成；自动化检查、实际运行验证与人工验收分别说明。研究、提议和计划不写成已实现成果。

Codex 完成回复只是当时的完成报告；WorkBuddy 消息的 `completed` 状态只表示该条消息结束，收集时标记为 `assistant_note`，不能据此认定整项任务完成。不同工具参与同一成果时按主题合并，保留来源与未解决限制，不重复计数。

公开摘要删除密钥、Cookie、身份和联系方式、私人会话细节、本机绝对路径、内部地址、私有仓库链接及原始会话 ID。涉及私人事务只保留可公开的概括，无法安全概括则跳过。

## 本地维护

需要 Python 3.11+、Git 和已登录的 GitHub CLI，无额外 Python 依赖。

```powershell
# 将 Codex 任务请求和完成报告收集到 Git 忽略的本地文件
python scripts/worklog.py collect --date 2026-10-14

# 同时收集 WorkBuddy；参数指向含 projects 的应用数据目录
python scripts/worklog.py collect --date 2026-10-14 --workbuddy-home "$env:USERPROFILE/.workbuddy" --workbuddy-home "$env:USERPROFILE/.workbuddy-ai"

# 历史补记支持 --until 结束日期；两种 --*-home 均可重复以合并旧目录

# Codex 阅读本地素材、按 templates/daily.md 撰写脱敏摘要后：
python scripts/worklog.py index
python scripts/worklog.py check
python -m unittest discover -s tests
git diff --check
```

`collect` 不调用模型，也不自动把原文变成公开日报。公开摘要由 Codex 整理并审阅。`check` 是常见敏感模式检查，不能替代语义脱敏。收集素材仅保存在 `.local/`，禁止强制加入 Git。

WorkBuddy 收集仅读取主会话的用户请求和助手文字备注，按请求、北京时间日期及消息状态保留最后备注，不读取工具输出、推理记录或子代理文件。显式指定的来源不存在或读取失败时停止收集，不按“没有工作”发布；尚未配置 WorkBuddy 时，原 Codex 单来源命令仍可使用。

发布时只暂存本次明确生成的公开文件，检查暂存内容，再提交和推送；不使用强制推送。失败时保留本地文件供重试，不更改其他项目。
